Скрипт выполняет только GET и не передаёт токен в вывод; приватные результаты исключены из Git.

## МойСклад

Создать отдельного сотрудника для интеграции: «Моя компания → Сотрудники → +Сотрудник». API-логин имеет вид `Логин@Название_Аккаунта`; email не заменяет его. В разделе токенов настроек пользователь может создать и скопировать токен; доступность раздела зависит от прав. Документированный API-способ — `POST /security/token` с Basic-авторизацией, затем Bearer. **Выдача токена отзывает прежние токены этого пользователя**, поэтому не выполнять её для владельца или уже используемой интеграции. Агент сейчас токен не выдаёт. [Сотрудники](https://support.moysklad.ru/hc/ru/управление%20аккаунтом/пользователи/сотрудники), [контракт авторизации](https://raw.githubusercontent.com/moysklad/api-remap-1.2-doc/master/md/_general.md).

Минимальный профиль раннего чтения: доступ к API, просмотр товаров/модификаций, складов и отчёта остатков, заказов покупателей, контрагентов, отгрузок, организаций и списков маркировки. Если магазин действительно сущность розничной точки, нужен её просмотр. Создание, изменение, удаление и проведение документов выключить. Административные и финансовые права не нужны. Это проект профиля: достаточность проверим безопасными GET-запросами; права по конкретному складу на стороне сервиса пока не доказаны. Индивидуальные роли зависят от тарифа. [Права API](https://raw.githubusercontent.com/moysklad/api-remap-1.2-doc/master/md/dictionaries/_employee.md), [роли](https://support.moysklad.ru/hc/ru/управление%20аккаунтом/пользователи/разграничение_доступа_настройка_прав_роли).

Внести самостоятельно:

- `MOYSKLAD_TOKEN` — токен выделенного пользователя.
- `MOYSKLAD_ACCOUNT_ID` — ID аккаунта, когда известен.
- `MOYSKLAD_SHOP_NAME` — название выбранного магазина; тип сущности уточним перед сопоставлением.
- `MOYSKLAD_WAREHOUSE_NAME`, `MOYSKLAD_WAREHOUSE_ID` — название и UUID единственного выбранного учётного склада. **До их подтверждения реальный обмен не настраивается.** Остатки других складов продажи не открывают, см. [REQ-320](SPEC.md#req-320).
- `MOYSKLAD_ORGANIZATION_ID`, `MOYSKLAD_RETAIL_PRICE_TYPE_ID`, `MOYSKLAD_WHOLESALE_PRICE_TYPE_ID` — UUID организации и двух типов цен. Если неизвестны, оставить пустыми до разрешённого чтения справочников.

Официальный sandbox endpoint не подтверждён. Для изменяющих испытаний подходит отдельный обычный аккаунт с синтетическими данными; пробный период сам по себе не отключает внешние действия. Проверить тариф аккаунта. [Тарифы](https://www.moysklad.ru/subscription/).

На 08.10.2026 обычный запрос пользователя расходует 3 единицы из 45 за 3 секунды, отчёт остатков — 5; общий лимит внутри пользовательского окна. С 01.12.2026 обычный запрос расходует 4 единицы. Не более 5 параллельных запросов пользователя, сжатие ответов обязательно. Обработчик учитывает 429 и заголовки лимитов. [Ограничения](https://raw.githubusercontent.com/moysklad/api-remap-1.2-doc/master/md/_restrictions.md).

`trackingCodes`/`trackingCodes1162` не доказывают полный DataMatrix. TASK-009 сравнит одежду, обувь и два экземпляра одного варианта с разрешённым контрольным сканированием. [Контракт кодов](https://raw.githubusercontent.com/moysklad/api-remap-1.2-doc/master/md/dictionaries/_tracking_code.md).

## СДЭК — к TASK-010

Рабочие ключи получают после подписания договора; доступны в [ЛК → Интеграция](https://lk.cdek.ru/integration/index) через «Создать ключ». Заполнить `CDEK_CLIENT_ID`, `CDEK_CLIENT_SECRET`, адрес `CDEK_API_BASE_URL=https://api.cdek.ru`. OAuth использует `client_credentials`; scope только чтения не подтверждён. Ранняя программа допускает авторизацию, справочники, тариф и чтение заказа; создание/изменение отправлений закрыто.

Есть тестовый хост `https://api.edu.cdek.ru` и опубликованные тестовые ключи: их владелец заносит локально. Общий контур не доказывает тарифы договора. **Ручные накладные доступны API только созданные после первой авторизации интеграционных ключей.** Сначала разрешённая рабочая OAuth-авторизация, затем менеджер создаёт отдельно согласованное контрольное ручное отправление. Внести `CDEK_CONTROL_TRACKING_NUMBER` и `CDEK_SENDER_CITY_CODE`, когда будут нужны. [Официальная документация API v2](https://apidoc.cdek.ru/).

## Реальный контрольный сценарий

Проверить заполненность нужных полей без вывода значений, подтвердить магазин и склад. Чтение ограничить необходимыми сущностями, отчёт обезличить. Перед изменением представить владельцу конкретные объекты, операции, последствия для резерва/остатков и способ очистки. Только после согласования разрешить этот сценарий. Доказательство записать в [ACCEPTANCE](ACCEPTANCE.md) с датой, средой, версией и отличием от имитации.
