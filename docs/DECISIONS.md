<a id="dec-015"></a>
### DEC-015 — Только выбранный учётный склад

08.10.2026, approved. Владелец указал один магазин и учётный склад; на уточнение общего пула ответил «Только выбранный учётный склад». Другие склады исключаются из доступного количества/резервирования. Название и ID уточняются до реального обмена. Основание — прямые сообщения владельца в текущем чате; действующее уточнение [REQ-320](SPEC.md#req-320). Ограничения конкурентных операций и отсутствие двойного вычитания сохраняются.

<a id="dec-016"></a>
### DEC-016 — Доступы и контрольные изменения по необходимости

08.10.2026, approved. Владелец поручил официально проверить получение/права/тестовые контуры, подготовить шаблоны и исключённые из Git локальные настройки; ключи не выводить. Контрольные изменения рабочих данных требуют согласования конкретных объектов и операций. Без доступов продолжать независимую работу и имитации; реальные испытания подтверждать отдельно. Источник — прямое сообщение владельца; [REQ-321](SPEC.md#req-321).

## Порядок новых решений

Добавлять стабильный DEC-ID, дату, статус (`proposed`, `approved`, `adopted`, `superseded`), решение, причину, последствия, источник согласования и заменяемый ID. `approved` — явное согласование владельца; `adopted` — техническое решение исполнителя в пределах утверждённых требований; `proposed` не разрешает менять бизнес-правило.

При согласованном изменении требования обновить SPEC и связать с DEC-ID, затем затронутые PLAN/ACCEPTANCE. Историю сохранить в Git. Значимое архитектурное решение отразить в ARCHITECTURE. Технические возможности подтверждать отдельными проверками, а не статусом решения.
