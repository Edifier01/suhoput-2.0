# Покрытие требований и приёмка

Назначение: связь полного [SPEC](SPEC.md#индекс-требований) с задачами, проверками и доказательствами. Состояния — только в [STATUS](STATUS.md), описание/зависимости задач — в [PLAN](PLAN.md).

## Правила матрицы

- Для каждого REQ есть строка ниже; **все условия исходного абзаца/строки обязательны**. Краткое имя — ориентир. Повторы ТЗ сохранены; один будущий сценарий может подтвердить несколько REQ.
- Все 62 строки исходной приёмки включены отдельно; дополнительные условия текста, переходов, архитектуры, ранних проверок и действий владельца также покрыты.
- Все требования связаны со стабильными TASK-ID из утверждённого PLAN. Эта связь не означает выполнения функции; до соответствующего испытания результат остаётся «не запускалась».
- CHK-ID стабилен. Сейчас указан способ будущей проверки, а не выполненный тест. При реализации конкретизировать шаги/команды/данные/среду без ослабления условий.
- «Не запускалась» и отсутствие доказательства означают отсутствие подтверждения. Денежные сценарии сначала проверяются имитациями; реальная цепочка ЮKassa/кассы — только последними.
- Доказательство: дата, тип (реальное внешнее испытание/имитация/ручная/статическая), команда/сценарий, результат, окружение и версия. Указать отличие рабочей копии от коммита; изменение поведения требует новой проверки или снятия актуальности прежнего подтверждения.
