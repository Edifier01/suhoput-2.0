Usage — проекция за месяц, не тариф и не фактический счёт провайдера; исходные usage-null не разрешают расписание. Учесть запросы минуты (~43200 запусков/30д), metadata/locks restic, ежедневное чтение для integrity и восстановление. Контроль требует фактических счётчиков/объёма и сверки с биллингом; расчёт по bytes без API-запросов не считать контролем всей стоимости. У VPS при чтении доступно72944947200 bytes, available RAM7197540352; это текущая выборка, не долгосрочная гарантия. При нехватке места/бюджета поднять ошибку, сохранить последнюю годную цепочку и согласовать ресурс; не удалять обязательные30д или сокращать расписание ради успешного статуса.

Порядок разрешённого пакета: owner policy → реальные узкие Put/Get/Delete synthetic control → новый ключ восстановления и проверка owner-доступа → stage binlog → base/archive/check → минутная цепочка и fault/lag controls → recovery в отдельный instance/каталог → retention/budget/units → реальные срабатывания timers → независимое ревью/CI. Ни документация, ни локальные fixture не заменяют эти испытания. Установка Release магазина/production/ЮKassa не входит в пакет.

Выбранный кандидат — restic0.19.1: защищённые полные логические snapshots с передачей только изменённых блоков, отдельные DB dumps с координатами и immutable закрытые binlogs. **Реальная совместимость с S3-B ещё не испытана.** Альтернатива — отдельные зашифрованные tar/SQL/log archives с собственным retention/catalog; она потребует дополнительного кода криптографии/полноты/удаления и здесь не выбрана. Согласованные ежедневная полная копия и30д не снижаются: каждая full snapshot должна восстанавливаться без рабочей площадки; хранение chain prerequisites до начала30д окна учитывается отдельно. Restic cache и live datadir не являются копией MariaDB.

Официальные источники прочитаны11.10.2026: [MariaDB dump](https://mariadb.com/docs/server/clients-and-utilities/backup-restore-and-import-clients/mariadb-dump) допускает single-transaction/master-data для InnoDB; [PITR](https://mariadb.com/docs/server/server-usage/backup-and-restore/mariadb-backup/point-in-time-recovery-pitr-mariadb-backup) требует replay от координат base; [S3 API](https://docs.selectel.ru/api/object-storage-s3/) не поддерживает Bucket Lifecycle/Encryption API, поэтому нужны клиентская защита и свой retention; [policy actions](https://docs.selectel.ru/s3/buckets/bucket-policy/about-bucket-policy/) ограничиваются object prefix; [оплата](https://docs.selectel.ru/s3/about/payment/) учитывает хранение, трафик и запросы. Версии серверов/API и реальные наблюдения — ACCEPTANCE. Источники доказывают выбор подхода, не исполнение пакета.

## Обследование без изменений

Для serial web-console вводить короткие команды; при необходимости разбивать ввод на небольшие части и нажимать Enter только после полного набора. При сбое ввода сначала отменить/очистить строку и визуально подтвердить чистое приглашение. Вывод службы/таймеров получать с `--no-pager`; если открыт pager, выйти из него и подтвердить shell до следующей команды. Прерванный ввод без Enter, команда в pager и исполненная команда без сохранённого результата не являются успешными доказательствами. Не читать полный DOM-снимок страницы консоли: адрес встроенного сеанса может содержать временный токен; использовать экран и узко выбранное поле ввода.

Входы — [ACCESS](ACCESS.md#infrastructure-inputs). Работать только с подтверждёнными объектами. Каждый результат записывать с UTC начала/получения, датой Europe/Moscow, командой без значений секретов, версией клиента/сервера, окружением, SHA кода и итогом. `not_run`, `access_denied`, `unsupported` и `observed` различаются. Отсутствие доступа не означает отсутствие ресурса.

1. Проверить форму локально, показывая только имена полей и заполненность. Секреты не source/dot-source как код; не печатать env, токены, private keys или полную конфигурацию. Сверить целевой VPS/бакет/домен и границы чтения по сведениям владельца. Не извлекать случайные цели из known_hosts и не искать пароли по личным папкам.
2. Сверить SSH host fingerprint через доверенный канал владельца/панель и соответствующую запись known_hosts. SSH — `StrictHostKeyChecking=yes`, без agent forwarding, туннелей и принятия неизвестного ключа. Начать с коротких команд. Для уже настроенного ключа использовать `BatchMode=yes`, `IdentitiesOnly=yes`, `ConnectTimeout=10`; при другом способе входа сначала определить безопасный ввод без передачи пароля в командную строку/отчёт. Не менять сервер ради подключения. Существующая запись known_hosts и отдельная независимая сверка fingerprint — разные доказательства. При зашифрованном ключе проверить только разрешённый владельцем локальный источник фразы в памяти; ошибку зависимости декодера отличать от неверной фразы. Не сохранять расшифрованный private key, не менять его фразу и не пробовать её как пароль сервера.
3. Снять версию ОС/ядра, CPU/RAM, файловые системы/свободное место/inodes, текущую нагрузку и синхронизацию часов. Подготовленные Linux-команды ниже запускаются отдельно, только после подтверждения цели. Отсутствующий инструмент или отказ права записать; ничего не устанавливать, не запускать нагрузочную проверку и не менять часовой пояс.

```sh
date -u +%Y-%m-%dT%H:%M:%SZ
id -u
uname -srm
cat /etc/os-release
nproc
free -b
df -PT
df -Pi
uptime
timedatectl show --property=Timezone --property=NTPSynchronized
ss -lnt
systemctl list-units --type=service --all --no-pager
systemctl list-timers --all --no-pager
```

4. Выяснить существующие сайты/БД, владельцев каталогов, web/PHP/DB версии, панель/контейнеры, задания и действующие копии через метаданные и разрешённые сведения владельца. Выполнять только версии установленного стека (`nginx -v`, `apache2 -v`, `php -v`, `php -m`, `mariadb --version` по наличию). Каталоги/БД в приватной записи связывать с метками сайта; публичный отчёт не содержит адресов доступа, имён учёток/бакетов или рабочих данных. Не выполнять `nginx -T`, полные `docker inspect`/env, `systemctl status` с журналами, вывод crontab/секретных конфигов. Не загружать рабочий WordPress через WP-CLI/HTTP ради инвентаризации: плагины/cron могут иметь побочные действия. В случае нехватки метаданных запросить узкую обезличенную выборку владельца.
5. При уже существующем разрешённом доступе к DB читать только метаданные, без бизнес-строк/дампа. Список доступных схем и версии получить через панель или ограниченного пользователя. Кандидат SQL для проверки возможностей, не выполненный сейчас: `SHOW VARIABLES WHERE Variable_name IN ('version','version_comment','log_bin','binlog_format','binlog_expire_logs_seconds','expire_logs_days','time_zone','system_time_zone','read_only');`. Отсутствующее поле помечать unknown; настройку binlog не менять. SQL-метаданные не доказывают RPO/RTO.
6. Для выбранного S3-бакета подготовлены HEAD Bucket, GET Location/Versioning/Policy в пределах действующих прав. Предпочтителен SDK с Signature v4, проверкой TLS и выбранным endpoint/регионом; версию инструмента записать при выполнении. AWS CLI локально не обнаружен — это не запрет другого согласованного клиента. Не перечислять все бакеты аккаунта, не читать содержимое резервных копий/объектов; при необходимости только согласованный prefix и обезличенные размеры/счётчики. Никаких PUT/DELETE, тестовой загрузки, смены типа/политики/версий/retention или создания новых ключей. Ошибку 403/404 разбирать с владельцем без расширения прав и перебора объектов.
7. Для подтверждённого домена прочитать NS, A/AAAA/CNAME, MX и TXT (SPF, `_dmarc`, подтверждённый `<selector>._domainkey`); например, `Resolve-DnsName -Name '<подтверждённое имя>' -Type NS` и отдельные запросы нужного типа. Не подставлять пример домена и не менять зону. При согласованном HTTPS-адресе исследовать только TLS handshake/сертификат (имя, цепь, срок), без GET страниц магазина и без ACME-заявки. Просмотр конфигурации почтовой услуги не включает AUTH, чтение ящика или отправку письма. DNS/сертификат/параметры SMTP не доказывают доставку.

Сырой материал — только в защищённом локальном каталоге вне Git, например `.cache/infrastructure`; запрет на публикацию секретов действует и там. Перед общим отчётом удалить/заменить адреса доступа, идентификаторы аккаунтов, данные клиентов и случайно полученные секреты. Полные серверные логи/дампы не собирать.
